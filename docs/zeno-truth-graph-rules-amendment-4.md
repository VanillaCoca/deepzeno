## 0. 本修订案不改变什么

v1 与 №1/№2/№3 的以下决策全部保留，本案与之兼容并强化：

- **最高信条：看一眼就懂**（v1 §0）。本案新增的「重入效率」是它下位的排序原则，不是竞争原则 —— 见 §1.3。
- 两层视图、同屏并置、不跳转（v1 §1、§2）。**本案不新增任何页面，且不改变画布几何**（见 §2.1）。
- 语义分层五条带及其纵向顺序 锚/前提/已定/待决/已排除（№1 §2、№3 §0）、密度跟生命周期（№1 §4）、位置承担结构。
- 安静依赖线四条件、带内多列、边路由三分法（№2、№3）。
- 绿红唯一语义、四形状、色盲冗余、确定性稳定布局（v1 §1.1、§4）。
- **truth 只读，一切判断变更回 sandbox**（v1 §7）。§5 的重组提案只改节点归属与排布，不改 status/content，见 §5.2。
- **确认是稀缺资源，确认必须是思考行为**（宪法修订案 №1 Iron Law 0；收件箱 K3/N2/NG2）。本案 §3 是对这条的**加固**，不是松绑 —— 见 §3.1 的自我纠正。
- 收件箱 K8 的两条确认闸门（`confirmability='needs_discussion'` 不给一键确认；`topicId=null` 确认前强制指派）。本案只管**入队**，不碰**可确认性**判定。

## 1. 诊断（为什么要修订）

### 1.1 三个缺口

现有文件把「这个项目现在是什么形状」回答得很完整，但有三处空白：

| # | 缺口 | 证据 |
|---|---|---|
| 1 | **没有重入态。** 全部规则描述的是稳态呈现，没有一条回答「我离开三周回来，先看什么」 | 产品战略层的北极星是 Re-entry Success Rate（产品所有者定，本 corpus 内未成文；两份 PRD 各自的北极星是它的下位指标），而呈现层没有对应表面。`ir-panel.tsx` 顶栏有一个「re-entry indicator」，但无内容规范 |
| 2 | **确认债的闸门装在出口，入口无闸。** 裁决收件箱（消费端）已建，但五个生产者持续写 `pending`，稀缺性靠消费端节流是杯水车薪 | 图1 案例：11 节点中 4 项待确认，项目级收件箱 15。2026-07-19 L3 巡逻现场：246 个 ir_watch 在 31 分钟内集体告警，抽样 40 条全响（该事件是否早于周上限生效，实现期核对） |
| 3 | **Agent 动态权无边界。** v1 §3.2 允许 agent 按内容选图表类型，但「每次访问呈现什么、折叠什么、强调什么」无规则 | 实现上靠默认值兜底；产品所有者提出的动态化诉求无处安放，导致要么不敢动、要么动过头 |

### 1.2 对「是否还需要固定范式」的裁决

**需要，但需要固定的东西比想象中少，且必须写清楚哪些不固定。**

论据（详见附 C）：

- 范式服务的约束在人这边，不在模型那边。需要稳定布局才能形成空间记忆的是人；只能在恒定背景上感知变化的是人；把可预测性当信任前提的还是人。模型变强改变的是**谁来设计范式**，不是**范式成形后要不要保持稳定**。这正是 v1 §1.1「用户的空间记忆不能每次被打乱」的原话。
- 自适应界面四十年的实证一致：**改位置有害，改显著性有益**。Office 2000 个性化菜单被微软自己关掉；对照实验里系统自适应菜单比静态还慢且最不受欢迎；唯一稳健有效的形态是 Ephemeral Adaptation —— 布局 100% 不动，预测项立刻显现、其余渐显。**注意：v1 §4.6 的三级透明度不是这个东西** —— 它是**用户选中**驱动的聚焦语言，不是系统预测驱动的适应。本案不复用该通道，见 §4.2。
- 2025–26 生成式 UI 的全部正面结果**只测过首次访问**；真实用户查询下偏好降至五五开；「用户能否学习每次都不同的界面」在学界仍是公开未解问题。而真相图谱是**每次都要回来的常驻物**，不是一次性解释物。
- 行业收敛方向一致：Vercel 生成式 UI 限定在开发者注册的组件内；OpenAI Apps SDK 强制第三方进入固定设计系统；Google A2UI 协议 2026-07 的 v0.9 明确从「组件发明」退回「设计系统目录」。

**结论：千人千面的正确颗粒度是 per-project（一次成形、显式演化），不是 per-visit（每次重画）。** 逐次即兴的界面每次访问都向用户征收一笔「重新看懂界面」的注意力税 —— 与铁律 2「宁漏勿错」的注意力预算精神直接冲突。

### 1.3 宗旨与最高信条的关系（裁决口径）

新增排序原则：**让用户以最短时间重建正确的心智模型，并抵达下一个判断。**

两者分工，不冲突：

| 原则 | 裁决什么 | 冲突时 |
|---|---|---|
| 最高信条「看一眼就懂」（v1 §0） | 用什么符号、概念、体裁（可学性） | **优先** |
| 重入效率（本案） | 什么先出现、什么被折叠、什么被强调（排序） | 让位 |

硬约束一条：**不为整洁牺牲不确定性与出处的可见性。** 一个认识论产品不能隐藏自己的认识论 —— 这是铁律 2 在呈现层的投影。

## 2. 重入态（Re-entry State）

### 2.1 形态与位置（对画布几何零影响）

**重入态是覆盖层（overlay），浮在全貌层上方，不挤压画布。**

- 画布（五条带、节点位置、多列换行）**几何完全不变**：重入态出现与消失，下方任何节点都不发生位移。这是它必须是 overlay 而不是「变高的聚合条」的唯一原因 —— 一个高度可变的顶栏会让全部节点在不同访问间上下移动，正是 v1 §1.1 与本案 §4.2 禁止的事。
- 关闭后收敛为 №1 §6 的全局待决聚合条常态，不留残余高度。
- 不换页、不跳转（v1 §2 同屏并置不破）。
- 长缺席变体（§2.4）内容较长时，overlay 内部滚动，**不撑高、不推挤画布**。

触发（确定性判定，不走模型）：

| 条件 | 结果 |
|---|---|
| 距水位线 < 24h 且无结构性变更 | 不进入重入态 |
| 距水位线 ≥ 24h，或存在结构性变更 | 重入态 overlay |
| 距水位线 ≥ 14d | 重入态 + 叙述变体（§2.4） |

**结构性变更**（纯结构判定，不含语义判断，故触发确定性成立）：出现新的 `active` 节点、发生 `supersedes` 边写入、`assumption` 被标记失效、`pending` 队列净增。注意与 §3.2 的「承重」不是同一概念 —— 承重判定含语义部分，不参与触发。

### 2.2 内容与排序（硬性）

重入态**恰好回答三个问题，按此固定顺序**，不得增删类别、不得改变段序：

1. **「你说过接下来要做什么」** —— 上次离开时的未竟意图（来源：最后一次 sandbox 会话的未决动作、用户 `/save` 的笔记）。
2. **「卡在哪」** —— 当前 blocked-on-you 的待决项 top-3，附下游影响数（复用收件箱的爆炸半径计算），尾部给「进收件箱看全部（N）」入口。**不在此处复制整个队列**，避免出现第二个队列。
3. **「变了什么」** —— 自水位线以来的状态迁移：新增已定、被否候选、被 supersede 的旧真相、失效的前提、Watchtower 告警。

段内条目排序依据是**后果**（爆炸半径），不是时间、不是置信度（镜像收件箱 K2）。

为什么是这三条且是这个顺序：任务恢复研究的一致发现是，人重入时的第一动作是看变更历史（约四成）与自己留下的前瞻线索，而不是看结构总览；有效的自留线索是**前瞻式的**（「我打算…」）而非回顾式摘要。恢复期本身很长 —— 只有约一成的会话在第一分钟内产出实质动作，平均要先浏览七个位置才动手。重入态的全部意义是把这七次浏览压缩掉。

### 2.3 禁止事项

| 禁止 | 理由 |
|---|---|
| 出现任何批量确认控件 | 收件箱 K3/N2；本案 §3 |
| 挤压或改变下方画布几何 | v1 §1.1；本案 §4.2 |
| 罗列全部变更 | 「元素只在改变理解时才出现」（v1 §0）。每段超过 5 条按后果截断并显式说明「另有 N 项次要变更」—— **禁止静默截断**（镜像 Watchtower N3） |
| 生成"上次以来的进展总结"式散文当默认形态 | 该形态已被行业验证为退化路径：Claude 记忆曾用生成式散文摘要，后改回可检视的离散条目。散文只在 §2.4 出现 |
| 第一段无数据时由模型推测用户意图填充 | 宁漏勿错。无数据则该段不渲染 |

### 2.4 长缺席变体（≥14d）

节点数与变更量都大时，人重建心智模型的成本超过逐条阅读的收益。此时重入态额外提供一段**叙述式回顾**：项目当前在回答什么问题、上次以来判断线怎么移动的、现在卡在哪。

- **每句必须挂出处**，点击回到对应节点（硬性，铁律 2 的呈现层投影）。
- 它是入口不是替代：读完仍落到 §2.2 的三段结构上。
- 这是本案允许模型自由生成文本的**唯一位置**，且它生成的是文本，不是界面结构。

### 2.5 水位线语义与数据依赖（给 Albert）

**水位线 `last_viewed_at`（每用户每项目）在重入态被用户关闭或滚动读完时更新**，不在面板打开瞬间更新 —— 打开即更新会让用户切走再回来时丢失尚未读完的 diff。同一会话内关闭后不再重复呈现。

| 需要 | 现状（待实现期核对） | 备注 |
|---|---|---|
| `last_viewed_at`（每用户每项目） | **疑似缺失，需新增** | 重入态基线，**最高优先级**；无此则 diff 无从计算 |
| 状态迁移历史 | `decision_log` 已存在（收件箱 JI-04 依赖它） | 若已记录 from/to/at/actor 则 §2.2 第三段直接可算，无需新表 |
| 未竟意图 | 需确认 sandbox 侧是否留存「下次要做什么」 | 若无，V1 只做后两段，第一段留空位而非编造 |

粒度待决（per-project vs per-topic）见附 D。

## 3. 分层入队：确认债的正解

### 3.1 先纠正一个错误提案

设计讨论中曾提出三个方案：非承重候选**自动晋升**为真相（带 provisional 标记）、**批量确认**、**超时默认采纳**。

**三个全部作废。** 分别违反：

- 自动晋升 → 铁律 4（candidate-only write，truth 只读）与收件箱 D0-NG2。
- 批量确认 → 收件箱 K3/N2：「批量按钮会把调查量兑换成盖章量」。
- 超时默认采纳 → Iron Law 0「确认必须是思考行为」。**沉默不是采纳信号。** 这是三者中最隐蔽的一条：它看起来只是省事，实际是把「用户没看见」记录成了「用户认可」，会系统性污染真相集，且污染不可见。

保留其中唯一正确的直觉：**确认债不能随规模线性增长。** 但解法不在出口。

### 3.2 正解：闸在入口

系统已有两级状态，只是没有被当作闸门使用：

| 状态 | 语义（现有） | 进收件箱？ |
|---|---|---|
| `idea` | 低置信，安静列着，不要求行动 | 否（收件箱 D0-NG4 / JI-06） |
| `pending` | 等你拍板的 candidate | 是 |

**分层确认 = 分层入队，不是分层放行。** 提取层决定新节点落成 `idea` 还是 `pending`；只有 `pending` 消耗确认注意力。任何东西都不会被自动确认为真相 —— **出口的严格性一分不减**，收件箱 K8 的两条闸门（needs_discussion / topic 指派）继续独立生效。

这与 Watchtower K3 是同一手法：**巡检频率与告警频率解耦**。此处是：**抽取频率与确认频率解耦。**

入队判据（给 Lixian，命中任一落 `pending`；全不命中落 `idea`）：

| 判据 | 说明 |
|---|---|
| **前提类** | `kind ∈ {principle, constraint, hypothesis}` —— 前提是别的判断的地基，错了连累下游（kind 枚举见 v1.3 §2.2；前提/判断的区分见 v1 §6.1） |
| **目标类** | `kind = goal` —— №1 §5.3 明确要求候选目标「出现在待决带，与其他候选无异，走同一套确认制」 |
| **重塑既有真相** | 带 `supersedes` / `contradicts` / `resolves` 边指向 `active` 节点（＝收件箱 Tier A） |
| **回答显式待决问题** | 有 `resolves` 边指向 open_question —— 用户已表达过「我在等这个」 |
| **告警** | `sourceLayer ∈ {watchtower, research}` 的告警候选，已有机制不变 |
| 全不命中 | 落 `idea`（典型：未挂任何问题、也不改动既有真相的新增 `plan/decision`、`task`、`milestone`） |

**动态升级（新增，硬性）**：`idea` 节点在下列任一情况发生时转 `pending` 入队 ——

1. 获得 ≥1 条下游依赖边（它变成承重的了）；
2. 用户在 sandbox 中引用它继续推进（用户自己把它当前提用了）；
3. **用户手动提升**（见 §3.3）。

这解决了「抽取时还看不出承重」的时序难题：**承重是动态判定的，一旦成真立刻入队。**

**写路径（硬性）**：idea→pending 一律经既有 `/api/ir/[id]/promote` 端点，**不存在任何直接改写 `ir_nodes.status` 的新代码路径**（收件箱 N1/JI-12、Watchtower N1 同一铁律）。

### 3.3 `idea` 的呈现纪律（给 Codex）

闸门要真正省注意力，`idea` 的呈现必须与 `pending` 明确分开，否则视觉上照样是债：

- **类型章**：`待观察`（灰，点线描边）。需在 №1 §3 的类型章表中新增一行 —— №1 §3 的目标是「初次使用者不需要图例」，新增可见类型而不给类型章会破坏该保证。
- **密度**：单行，`◐` 70% 不透明度（v1.3 §2.1 已定）。该 70% 是**基线**；用户选中态的三级透明度（v1 §4.6）覆盖它，不相乘。
- **位置**：待决带末尾的折叠区「另有 N 条待观察」，默认折叠。**这是本案对 №3 §2「待决带整宽卡片」的一处细化**：折叠区是待决带内的附属结构，展开后仍为单行列表，不使用完整卡片。
- **不出现确认按钮**。要裁决它，两条路径：进 sandbox 讨论，或**手动提升为待裁决**（`promote`，用户主动动作，不违反 Iron Law 0；v1.3 §9 已有该操作的键位待决项）。
- 计数：`idea` 天然不计入 pending badge（收件箱 D1§3 的 `countIRNodesByStatus('pending')` 已保证），**无需新增查询口径**；本案只要求「待决过多」提示阈值同样排除 idea。

### 3.4 指标

沿用收件箱北极星（pending 停留时长中位数 ↓，确认率不可 gaming），新增两条闸门健康度：

| 指标 | 含义 | 警戒 |
|---|---|---|
| 入队率 = pending 新增 / 全部新增 | 闸门是否真的在挡 | 持续 > 50% ⇒ 判据失效，退化成全量入队 |
| idea 升级率 = 转 pending / idea 总量 | 判据是否漏掉了真正承重的东西 | 持续 > 30% ⇒ 静态判据过窄，需补 |

两条同时踩线说明分层没有意义，应退回全量入队并重新设计判据 —— **写下这个退出条件，是为了让这次分层可以被证伪。**

## 4. Agent 动态权边界

### 4.1 三层划分

| 层 | 内容 | 动态性 |
|---|---|---|
| **L1 语义契约** | 节点 kind/status、6 种边关系、绿红语义、四形状、五条带顺序、出处与 supersede 链 | **固定**。信任资产，任何项目任何时刻一致 |
| **L2 呈现** | 重入态内容与排序、长缺席叙述、图表类型（内容驱动） | **文法内动态**：只能在既有组件与既有视觉语言里选择与组合 |
| **L3 交互策略** | 什么时候问、在哪问、要不要现在打断 | **完全动态**：按在场状态与后果实时决策 |

### 4.2 可变 / 不可变清单（硬性）

| Agent **可以**变 | 变的频率 | Agent **永不**变 |
|---|---|---|
| 重入态三段**内部**的条目选择与截断 | 每次重入 | 重入态的三段构成与段序（§2.2） |
| 重入态是否出现 | —— **不可变，由 §2.1 确定性触发决定** | —— |
| 长缺席叙述的措辞与组织 | 每次触发 | 叙述必须挂出处（§2.4） |
| 图表类型（v1 §3.2 决策树） | **仅内容形态改变时**，非每次访问 | 视觉语言（v1 §3.1）；同一内容不得在不同访问间换图 |
| 提问时机、渲染通道、是否合批（§4.4） | 实时 | 是否**可确认**（收件箱 K8 两闸门说了算） |
| 是否发出重组提案（§5） | 受冷却限制 | 结构本身（提案需用户采纳才生效） |

**永不由 Agent 变动的还包括：**

| 项 | 谁决定 | 依据 |
|---|---|---|
| 节点位置与五条带顺序 | 仅三种情况变：新 truth 确认后的增量重排（v1 §1.1）、用户采纳重组提案（§5）、容器宽度变化导致多列换行（№3 §2）。**「访问」不是其中之一** | v1 §1.1、№1 §2、№3 §0 |
| 前提折叠条开合 | 确定性：前提数 ≤4 展开，>4 折叠（№2 §4）。**不可由 agent 每次改** —— №2 §2 条件 3 让边的可见性依赖折叠态，agent 每次改会导致依赖线每次不同 | №2 §2、§4 |
| 已排除抽屉、superseded 隐藏 | 确定性默认折叠/隐藏 | №1 §2、v1 §8 |
| 三级透明度聚焦通道 | **用户选中专用**。Agent 不得占用该通道 | v1 §4.6 |
| 是否需要**入队** | §3.2 判据，非措辞裁量 | 本案 §3 |

**Agent 表达焦点的合法手段**（因为 opacity 通道被用户选中占用）：在重入态里**点名节点 + 提供跳转**，以及 №2 §3 已有的「一次性入场微动画」。不得持续改变任何节点的常态视觉权重。

一句话：**Agent 调注意力的入口，不调家具的位置。**

### 4.3 路由 = 确定性规则 + 少量模型判断

呈现路由**不整体交给模型**。分工按「每次模型调用应当对应一个真正需要判断的决策」：

| 交给代码（确定性） | 交给模型（需要判断） |
|---|---|
| 重入态触发（时间阈值、结构性变更检测，§2.1） | 重入态各段的条目选择与截断 |
| 成熟度阶梯（节点数 → 是否画图，v1 §8 已定） | 长缺席叙述的组织 |
| 折叠阈值（前提 ≤4 展开，№2 §4） | 入队判据里「是否重塑既有真相」的语义判定 |
| 入队判据的结构部分（kind、边的存在性）与动态升级 | reframe 检测（§5） |
| 排序（爆炸半径、时间） | 图表类型选择（v1 §3.2，已有权限） |

理由有二：确定性部分每次结果一致，可测试、可解释、零 token；且在稳定框架内，**「选得准」才是价值杠杆** —— 对照实验显示，把预测准确率从五成提到七成，速度、使用率、满意度同时提升，而算法透明度对性能无显著影响。把模型算力花在选择质量上，比花在形态发明上回报高得多。

### 4.4 L3：交互策略（回答「信息不够时怎么督促用户」）

三连问分流，全部在 L3，不改变任何呈现结构：

1. **事实缺口还是判断缺口？** 事实 → 派调研 Agent 自查（已有能力，图1 案例已正确使用）。判断 → 进 2。
2. **值得打断吗？** 用后果排序（爆炸半径）。低后果的不打断，落 `idea` 或在重入态里合批出现。
3. **用户在不在？** 在场 → 内联问题卡 + 推荐选项；离场 → 入队，回来时进重入态第二段。

**同一个待决对象，变的是渲染通道，不是形态。** 用户说「我出门了，你先做着」之后仍然弹确认窗是错的 —— 但正确的修复是换通道，不是重画界面。

督促的形态不是弹窗，是**让缺口的代价可见**（「这个待决卡住 3 个候选」）。

## 5. 结构重组 = 显式提案事件

### 5.1 规则

Agent 检测到项目发生 reframe 时，**提案，绝不静默重排**。

适用范围（重要）：**仅限 №1 §5.3 的自动转化规则未覆盖的重组。** goal 固化接管锚位、原锚问题被 `resolves` 这条路径已由提取层自动处理（№1 §5.3、§7），本案不为它增设第二条提案路径。

触发信号（模型判定）：

| 信号 | 例 |
|---|---|
| topic 内出现两个互不相交的节点簇 | 「设计↔开发交接」里长出一整支定价讨论 |
| 锚原则被新判断推翻（非 goal 固化路径） | —— |
| 大量节点被 supersede，叙事主线转移 | —— |

提案 payload（硬性，全部四项）：

1. 一句话说明「什么变了」；
2. 结构 diff 预览：**点名**哪些节点会挪到哪（镜像收件箱 R1：只写「影响若干节点」不合格）；
3. 影响：哪些已确认真相的所属关系会变；
4. 动作三选一：**采纳 / 进 sandbox 讨论 / 拒绝**。

关于「采纳」与 v1 §7.2：v1 §7.2 禁止的是**手动调整图**（手动连线、手动改关系类型）—— 用户在图上自行编辑结构。本案的采纳是**对系统提案的一次批准**，形态与 v1 §6.4 的假设失效开关同族（用户按钮只切换状态并触发系统行为，不自行编辑内容），且**不触碰任何节点的 status 与 content**。凡涉及判断本身是否成立的疑问，走第二个动作进 sandbox（v1 §7.4/§7.5）。

采纳后旧结构写入 `topic_relations` 的 lineage（№1 §5.3 已有数据机制）。**注意：`topic_relations` 的可视化在 v1.3 §10 被明确列为 out of scope（归未来的 Topic Explorer）**，因此「可回看」在 V1 只保证数据留痕，界面回看依赖 Topic Explorer，属 V1.5。实现期需明确重组写入 4 个枚举值中的哪一个。

### 5.2 与假设失效机制的关系

v1 §6.4（假设失效）与本节都以**「系统不代替用户改判断」**收尾，但触发方向相反，不可混谈：

| | 谁触发 | 系统做什么 |
|---|---|---|
| v1 §6.4 假设失效 | **用户**报告外部世界变了（唯一入口） | 高亮下游，不自动降级 |
| §5 结构重组 | **系统**检测到 reframe 并提案 | 等用户采纳，不静默执行 |

**重组只改变节点的归属与排布，绝不改变任何节点的 status 或 content。** 因此不触碰 v1 §7 truth 只读铁律。

### 5.3 禁止

| 禁止 | 理由 |
|---|---|
| 静默重排 | v1 §1.1 空间记忆；自适应界面实证：改位置是自适应 UI 最主要的失败原因 |
| 提案里只给结论不给 diff | 收件箱 R2/N3 同款：「把 diff 成本退还给用户」 |
| 高频提案 | 提案是重打扰，适用 Watchtower K3 的去重＋冷却＋上限；同一 topic 的重组提案被拒后进入冷却期（时长见附 D） |

## 6. 一次性透镜：V1 明确不做（记录决策，避免重复辩论）

「Agent 为某个时刻生成定制 HTML 交互视图」这一形态（产品所有者的原始诉求形态）**V1 不做**。

- 理由：V1 的差异化本体是家具的稳定性与重入效率，不是一次性演出的惊艳度。生成式界面的正面证据全部落在一次性解释物上，与常驻工作面无关。先把重入态与分层入队做扎实。
- **保留的升格路径**（V1.5 及以后）：透镜读同一份 L1 语义契约，默认阅后即焚；用户「钉住」→ 成为该项目常驻视图；被多个项目复用 → 提案进入 L2 组件文法。演出可以升格成家具，但必须经过「被人钉住」这道人类投票。
- 复议条件：重入态与分层入队上线且 §3.4 指标稳定后。

## 附 A：本修订案新增决策清单

1. 需要固定范式；动态化的颗粒度是 per-project，不是 per-visit
2. 新增排序原则「重入效率」，位阶在最高信条之下；硬约束：不为整洁牺牲出处与不确定性可见性
3. 重入态 = overlay，画布几何零影响，非新页面、非可变高度顶栏
4. 重入态触发确定性（含「结构性变更」的纯结构定义，区别于含语义的「承重」）
5. 重入态恰好三段：未竟意图 / 卡在哪 / 变了什么；段序固定不可变；第二段只给 top-3 + 收件箱入口
6. 长缺席（≥14d）叙述变体，每句必须挂出处；模型自由生成文本的唯一位置
7. 水位线在读完/关闭时更新，非打开时更新
8. **作废**：自动晋升 / 批量确认 / 超时默认采纳三个提案
9. 分层确认 = 分层入队：闸在 `idea`/`pending` 入口，出口严格性不变，K8 两闸门独立生效
10. 入队判据五条（前提类 / 目标类 / 重塑既有真相 / 回答显式问题 / 告警）；全不命中落 idea
11. 动态升级三条：获得下游依赖 / 被用户引用 / 用户手动 promote
12. idea→pending 一律经 `/api/ir/[id]/promote`，无新写路径
13. idea 呈现纪律：新增「待观察」类型章、单行、折叠区、无确认按钮、可手动提升
14. 闸门健康度双指标与退出条件（入队率 >50% 且升级率 >30% ⇒ 分层失效）
15. Agent 动态权三层：L1 固定 / L2 文法内 / L3 完全动态
16. 可变—不可变清单：Agent 调注意力的入口，不调家具的位置
17. 三级透明度通道为用户选中专用；Agent 焦点只能用点名 + 一次性入场动画
18. 折叠态、节点位置、图表类型的"每次访问可变"权限被明确否定
19. 路由 = 确定性代码为骨架 + 模型只做真正需要判断的部分
20. L3 三连问分流：事实/判断 → 后果 → 在场；变通道不变形态
21. 结构重组 = 显式提案事件，四项 payload，三动作（含进 sandbox）；仅限 №1 §5.3 未覆盖的重组
22. 重组只改归属与排布，不改 status/content；lineage 界面回看依赖 Topic Explorer（V1.5）
23. 重组提案适用去重＋冷却＋上限
24. 一次性透镜 V1 不做，保留「钉住即升格」路径与复议条件
